## 1. 架构总览

```
你在 GitHub 网页端编辑（不装任何环境）
  data/*.json        内容数据
  content/*.md       详情长文
        │  commit
        ▼
GitHub Actions（临时构建容器，跑完即销毁）
  node build.js
   ① 读 data/，校验必填字段
   ② md → HTML（markdown-it）
   ③ 模板函数拼出 N+2 个 HTML
   ④ CSS 分层拼接为 1 个文件，JS 原样拷贝
        │  产物作为 artifact 上传
        ▼
GitHub Pages（静态托管 + 全球 CDN + 免费 HTTPS）
        │
        ▼
浏览器：N+2 个 HTML + 1 个 CSS + 1 个 JS，无第三方库、无 fetch 内容
```

页面数口径：**1 个首页 + N 个详情页 + 1 个 404**，N = 有量化结果的项目数。设计期看 `inputs.env` 的 `*_HIGHLIGHT` 是否非空；实现期由 `data/projects.json` 的 `highlight` 字段决定——构建只读 `data/`，不读 `inputs.env`（ADR-B3）。当前 N=3，即 5 个 HTML。N 变化不影响本架构任何结论。

一句话：**源文件是数据与模板，线上是构建产物**。中间那层构建脚本是整个架构唯一的“活动部件”，也是唯一可能出错的地方。

## 2. 技术架构

| 层 | 选型 | 理由 | 代价 |
|---|---|---|---|
| 内容格式 | JSON（结构化）+ Markdown（长文） | 网页端可编辑，diff 可读，天然支持“加项目不改代码” | 必须经过构建才能变成页面 |
| 构建 | 自写 Node 脚本（约 150–200 行）+ `markdown-it` | 零运行时依赖、无框架锁定、出错时你能直接看懂脚本 | 脚本自己维护；`markdown-it` 成为构建期唯一第三方依赖 |
| 模板 | 手写 JS 函数返回字符串 | 所有页面共用 head/nav/footer/卡片，函数足够；学不到模板语法，也就不会依赖它 | 无模板语法糖，复杂布局会写成拼接串 |
| 样式 | 原生 CSS，分层源文件 → 构建时拼接为单文件 | 满足 N4「单文件 ≤ 12KB」，又不必在一个文件里翻 800 行 | 无嵌套、无作用域隔离；靠命名约定（§6） |
| 交互 | 原生 JS，单一入口 `main.js` ≤ 4KB | D14；只需 `IntersectionObserver` 与打印按钮 | DOM 操作手写，无框架兜底 |
| 托管 | GitHub Pages | 免费、自带 HTTPS 与 CDN、与代码同源 | 无服务端、无请求日志（§4.11 的统计因此只能走第三方） |
| 发布 | GitHub Actions + `deploy-pages` | 推送即发布，不需要本地环境 | Action 版本会迭代；失败要读日志 |
| 统计 | 预留，第三方聚合 | 零后端零运维 | 数据在第三方、可能被拦截漏计 |

**ADR-B1（构建方式：乙 · 已确认 2026-10-30）**

| 方案 | 做法 | 代价 |
|---|---|---|
| 甲 零构建 | 手写 4 个 HTML | 每改内容手改 HTML，第二详情页必复制冗余结构；违反已冻结的 D7 与 §4.5 |
| **乙 自写脚本（已选）** | Node 脚本 + `markdown-it` | 维护 200 行脚本；引入 1 个构建期依赖 |
| 丙 静态生成器（11ty） | 现成工具 | 30+ 传递依赖，与 D4 冲突；出问题需读别人的实现 |

放弃甲：与已冻结的 §4.5「加一个项目 = 追加一条数据 + 一个 md，模板零改动」直接冲突。放弃丙：30+ 传递依赖与 D4 冲突，且故障排查需读他人实现。

**D4 的适用解释**（本决策的一部分，实现期间以此为准）：**运行期零依赖**是硬约束，浏览器最终只收到 HTML/CSS/JS，不加载任何第三方库；**构建期允许 1 个登记依赖** `markdown-it`。换言之 D4 约束的是产物，不是构建过程。改为甲或丙须走需求变更请求。

**ADR-B2（仓库可见性：public · 已确认 2026-10-30）**

public 仓库可免费启用 Pages（private 仓库需付费账户）。代价是站点源码与 `data/` 内容公开可见，因此 `inputs.env` 不得写入手机号、住址、在职公司内部信息；联系方式只保留邮箱与 GitHub。

**ADR-B3（`docs/` 与源码隔离：设计过程文件不参与构建 · 已确认 2026-10-30）**

`docs/` 是设计过程产物，不是项目源码。`inputs.env` 只是给人看的输入清单，**构建流程不得读取它**：

| 约束 | 违反判定 |
|---|---|
| `build.js` 与 `src/` 下任何文件都不得出现 `docs/` 路径；构建只依赖 `data/`、`content/`、`src/` | 构建脚本里出现 `docs/` 字面量路径 |
| `inputs.env` 的值由人工转写进 `data/*.json`；转写后 `data/` 是实现期唯一事实源，两者允许不一致 | 页面内容只能从 `inputs.env` 推出、`data/` 里找不到对应字段 |
| `docs/` 不进入 `dist/` | 产物里出现 `.md`、`.env` |

代价：同一份内容在 `inputs.env`（设计输入）与 `data/`（实现数据）各存一次，需要人工同步一次。换来的是——**删掉整个 `docs/` 目录，站点仍能正常构建**；页面内容出问题时只需在 `data/` 一处排查。

## 3. 中间件与依赖

| 依赖 | 用途 | 不用会怎样 | 失效后果 |
|---|---|---|---|
| Node.js（Actions 内置） | 执行构建脚本 | 只能手写 HTML（方案甲） | 构建无法启动，线上保持旧版 |
| `markdown-it`（构建期） | md → HTML | 需自写解析器，表格/嵌套列表易错，约 +6h | 构建报错，旧版继续服务 |
| `package-lock.json`（版本锁定） | 锁定 `markdown-it` 及其传递依赖的确切版本 | 每次安装可能取到不同小版本，同一份 md 渲染结果漂移 | 渲染差异无法复现，只能逐版本试 |
| `actions/checkout` | 取仓库代码 | 构建无源文件可读 | 流水线失败 |
| `actions/setup-node` | 固定 Node 版本 | 用容器默认版本，行为可能漂移 | 版本差异导致构建异常 |
| `actions/upload-pages-artifact` + `deploy-pages` | 产物发布 | 需手动把 `dist/` 推到 `gh-pages` 分支 | 站点不更新 |

**运行时没有中间件。** 没有数据库、没有服务端、没有鉴权、没有缓存层——CDN 与 HTTPS 由 Pages 承担，不在本项目维护范围内。

## 4. 核心业务流

**4.1 内容变更流（主链路）**

你在网页端改 md 或 json → commit 到 `main` → Actions 触发 → 构建 → 产物上传 → 发布 → 线上更新（3 分钟内）。

异常分支：
- 必填字段缺失 → 脚本以非零码退出 → **Actions 红，线上保持上一个成功版本**（不会出现半成品）
- 引用了不存在的 md 文件 → 同上
- `highlight` 为空 → **不中断构建**，只打警告，该卡片从首页过滤（spec §4.2）
- CSS 拼接后超 12KB → **不中断构建**，但构建必须把单文件未压缩体积写入 Actions 摘要，超限时该行标红；验收以摘要输出为准（预算是验收项，不是构建门禁）

**4.2 访问流**

浏览器 → Pages CDN → HTML（首屏内容随 HTML 到达）→ CSS → JS 渐进增强。

异常分支：
- 路径不存在 → `404.html`（含返回首页链接）
- `/projects/不存在的slug/` → 同样落到 `404.html`；纯静态托管不生成重定向页，也不做 slug 模糊匹配
- JS 被拦截或加载失败 → 内容完整可读，仅少入场动效（V5/V6）
- 尾斜杠不一致 → Pages 301 跳转；内部链接统一带尾斜杠，避免多余跳转

**4.3 打印流**

`Ctrl+P` → `print.css` 接管 → 隐藏导航与按钮 → 卡片/表格禁止跨页切断 → 外链在文本后打印 URL → 生成 PDF。

异常分支：外链是内部锚点或站内路由 → 不打印 URL（spec §4.6）；内容超一页 → 按章节分页，不在表格中间断开。

## 5. 人工介入点

只有 6 处需要你亲自做，其余由实现方完成。完整步骤与卡点见 `learning-map.md` §2。

| 时点 | 你的动作 | 阻塞 |
|---|---|---|
| 开工前 | O1–O3：建 public 仓库、Pages 源设为 Actions、跑通首次部署 | **是**，不通则无法上线 |
| 并行 | O4：填 `inputs.env`（1–2h） | 阻塞全部页面内容 |
| 并行 | O5：录屏、架构图、量化指标表（6–10h，全项目最大时间块） | 阻塞详情页内容 |
| 上线后可选 | O5：买域名 + 解析 + 强制 HTTPS | 否 |
| 上线前 | O8：手机打开、`Ctrl+P`、禁用 JS 三项自检 | 否，但影响验收 |

**费用：0 元可上线。** 无需购买服务器——Pages 提供托管、CDN 与 HTTPS。域名约 ¥100/年，属可选。

**你需要提供的信息**：全部集中在 `docs/02-design/inputs.env`。key 已按分组列好，你只填等号右边；留空的 key 会让对应页面内容无法生成。

该文件是**设计输入，不是运行时配置**：构建脚本不读它（ADR-B3），值需转写进 `data/*.json` 才会出现在页面上。也就是说填完 `inputs.env` 后还需要一次转写，这一步由实现方完成，你只负责把值填对。

## 6. 开发规范

| 类别 | 规范 | 违反时的具体表现 |
|---|---|---|
| 文件命名 | `kebab-case`，目录同理 | 出现 `Index.html`、`projectList.js` 即视为违反 |
| 数据字段 | `camelCase`，字段名与 spec §4 术语一致 | 同一概念出现 `projectName` 与 `title` 两种写法 |
| CSS 类名 | 两层 BEM：`.card`、`.card__title`；状态类 `.is-active` | 出现 `.red-text`、`.mt20` 这类描述外观的类名 |
| CSS 分层 | 拼接顺序固定 `tokens → base → layout → components → pages → print` | 在 `components` 里写死色值（应使用 `var(--color-*)`） |
| CSS 预算 | 构建时打印单文件未压缩体积；超 12KB 需说明 | 无记录地超限 |
| JS | 单一入口，`defer` 加载；无内联 `onclick`；无第三方 | 出现 `<script>` 内联逻辑或 `import` 外部 URL |
| 文案 | 只存在于 `data/` 与 `content/` | 模板里搜到任何中文展示文案 |
| 图片 | WebP 或 PNG，单张 ≤ 200KB，宽度 ≤ 1600px | 出现 2MB 截图、未压缩的原始照片 |
| 提交信息 | 内容改动与代码改动分开提交，一句话说清改了什么 | 出现「update」「修改一下」这类无信息提交 |
| 文档隔离 | 构建不读 `docs/`；内容只能经 `data/` 与 `content/` 进入页面 | `build.js` 或 `src/` 里出现 `docs/` 路径；`dist/` 里出现 `.md`/`.env` |
| 产物 | `dist/` 不提交，由构建生成 | 仓库里出现 `dist/` |
| 分支 | 单人线性提交到 `main`，不建长期分支 | 出现 `dev`、`test` 长期分支 |

## 7. 目录结构

```
resume_website/
├─ README.md                      项目状态、目录说明与文档索引
├─ package.json                   构建依赖与版本（D 阶段启用）
├─ .gitignore                     忽略 dist/、node_modules/、密钥
├─ .github/workflows/deploy.yml   构建与发布流水线
├─ data/
│   ├─ profile.json               姓名、定位句、标签、联系方式
│   ├─ projects.json              项目列表（卡片数据 + slug）
│   └─ experience.json            经历时间线
├─ content/projects/*.md          项目详情长文，每项目一篇
├─ src/
│   ├─ templates/                 layout / index / project / 404
│   ├─ styles/                    tokens / base / layout / components / pages / print
│   ├─ scripts/main.js            唯一 JS 入口
│   └─ assets/                    图标、截图
├─ build.js                       构建脚本
├─ dist/                          构建产物（不提交）
└─ docs/                          四阶段文档
```

| 目录 | 职责 | 禁止放什么 |
|---|---|---|
| `data/` | 结构化内容，唯一数据源 | 长文（放 `content/`）、HTML 片段 |
| `content/projects/` | 详情页长文 | 样式、脚本、内联 HTML 结构 |
| `src/templates/` | 页面骨架与渲染函数 | 任何展示性文案字面量 |
| `src/styles/` | 分层样式 | HTML、`!important` 兜底 |
| `src/scripts/` | 渐进增强逻辑 | 内容渲染、第三方脚本 |
| `src/assets/` | 图片与图标 | >50MB 视频（用外链） |
| `build.js` | 构建入口 | 被 `src/` 内的文件反向引用 |
| `dist/` | 构建产物，含构建生成的 `robots.txt` | 手工修改（下次构建即被覆盖） |
| `docs/` | 四阶段**设计过程**文档，不参与构建（ADR-B3） | 被 `build.js`/`src/` 引用；实现代码 |
| `README.md` | 项目状态、目录说明、文档索引 | 功能细节（放 `docs/`） |
| `package.json` | 构建依赖与版本声明 | 业务配置（放 `data/`） |
| `.gitignore` | 排除产物与密钥 | 把 `inputs.env` 等公开内容误排掉 |

## 9. 风险与验证

| 风险 | 影响 | 验证方式 |
|---|---|---|
| Actions 首次配置失败 | 站点不上线 | 开工首日跑通 O3，确认你能看懂红叉停在哪一步 |
| 构建失败导致内容不更新 | 改了看不到 | 故意删一个必填字段，确认 Actions 变红且线上仍是旧版 |
| 网页端改 JSON 语法错误 | 同上，且难自查 | 同上；常见于 O4 填 `inputs.env` 的时期 |
| 域名解析未生效 | 自定义域名打不开 | DNS 查询工具确认 CNAME 已指向；证书签发最长 24h |
| CSS 超 12KB | 弱网首屏变慢 | 构建时打印体积，超限即记录原因 |
| `dist/` 被误提交 | 仓库污染、冲突频发 | `.gitignore` + 提交前看文件数 |
| 视频过大 | 仓库膨胀、克隆变慢 | 视频走外链，仓库只存截图 |
| 依赖版本漂移（`package-lock.json` 缺失或被忽略） | 同一份 md 在不同时间渲染结果不一致 | 提交锁文件；构建日志打印 `markdown-it` 实际版本 |
| Actions 大版本废弃（v3→v4 已发生过一次） | 流水线失效且不报错，站点静默停更 | Action 固定主版本号（如 `@v4`）；每半年看 Actions 页最近一次运行时间 |
