原 v0.1/v0.2 里 C-1…C-10 是「字段级约束该不该更严」这一类问题。你的判断成立：**本站没有后端、没有数据库、没有第二个人写数据**，库表级约束在这里没有收益，只会变成维护负担。所以十条全部按下表处置，不再逐条问你。

## 3. 前几轮的裁决留档

### 裁决点 1：TBD-4 视觉方向 —— 已裁决（2026-10-30）

C 阶段不产出视觉样张，只产出页面展示要素；视觉与交互放 D 阶段 spec 定稿。落地：`01-requirements/requirements-spec.md` §8 TBD-4 行改为不阻塞、§10 改 [D 阶段]、版本 v0.3。

### 裁决点 2：B 阶段冻结 —— 已裁决（2026-10-30）

`02-design/architecture.md` 状态改「已冻结」（v0.8）；冻结后仍可增量修订，走该文档 §11 变更记录。

### 裁决点 3：`.pen` 文件名去掉像素宽度 —— 已裁决（2026-10-30）

格式 `<页面>[-<模块>]-<形态>.pen`，形态 `pc`=1440、`mobile`=375，由生成器 `checkDevice()` 校验。5 个文件：`home-pc` / `home-mobile` / `detail-pc` / `404-mobile` / `print-home-pc`。

### 裁决点 4：数据文档的强度 —— 已裁决（2026-10-30）

无后端、无数据库 → 数据文档只做「实体 + 要素 + 页面落点」，不做库表级约束；页面设计由我方定。

| 方案 | 结论 |
|---|---|
| 字段级强约束（长度/正则/唯一/排序，违规构建失败） | 否决：无收益，且挡「先发再改」 |
| **要素清单 + 影响渲染的规则（采用）** | 保留可读性与落点映射，删除无收益校验 |
